## What's new

Module rebuilt from the SusFS ports that landed after 1.2.23's rebuild
(upstream `7565d75` with the slot-handback fix `9b27112`, plus `a5e7ba5` and
`11e692c`, integrated as module source `8c90691` and finished with the
same-day review follow-ups as source `b5c994d`; upstream base `c2a5575`
unchanged). One headline rework plus two hardening ports:

- **Open redirection no longer pins anything.** A redirected rule used to
  keep the target's `struct path` - a dentry and a mount pinned for the
  module's whole lifetime, a per-rule cost that could also hold a umount
  open. The redirect decision now happens at the open syscall entry, where
  the name is still in registers: the open, openat, openat2 and compat open
  entries are served by replacement wrappers on the module's syscall-entry
  layer, each wrapper asks the rule table with the path it is about to open
  and re-runs the call on the redirect target when a matching rule answers.
  A rule is now only numbers (target inode, device, generation), the
  add-time statfs snapshot and the two pathnames, and the open path never
  holds a reference, so a rule can neither delay a umount nor pin device
  storage.
- **Rewriting a rule on a full table works.** A rewrite of an
  already-listed rule used to spend a fresh slot while the old one was
  emptied inside the same add, so a steadily rewritten (rather than grown)
  table drifted to its 64-slot cap and then refused. The rewrite now hands
  its own slot back after one grace period and retakes it, and `clear`
  pays one grace period for the whole table instead of one per rule
  (upstream `9b27112`).
- **Kernel audit denials are hidden at both ends.** The avc-spoof
  pre-handler rewrote only the target sid, so a denial whose su domain is
  the source ("denied ... scontext=u:r:ksu:s0") still leaked, and that is
  the line root-hiding detectors actually grep for. Both ends are now
  matched and substituted independently (upstream `a5e7ba5`); a sid of 0 is
  still never matched. The `/proc/susfs_avc_spoof` output is unchanged.
- **The cache-flush helper is resolved by name at load.** The build-time
  pick of the dcache flush helper left an undefined `dcache_clean_inval_poc`
  import in the module, and a Samsung kernel keeping the older
  `__flush_dcache_area` spelling would refuse to load it (upstream issue
  #77). Both spellings are now looked up at load, new first; a kernel
  carrying neither refuses patching cleanly up front instead of failing one
  patch at a time (upstream `11e692c`).
- Everything the app relies on keeps its shape: the `/proc` rule and hooks
  output stays byte-identical (the hooks line's leading field is now the
  wrapper layer's own armed state), the reverse faces (readlink, statfs,
  maps, fdinfo) keep the Samsung-adapted umount-app and KSU gates, and the
  five uid schemes are accepted exactly as before.

## Validation

Module size is 545,232 bytes stripped (was 522,448; the syscall-entry
wrapper layer accounts for the growth). Against the 1.2.23 module the
kernel import surface loses exactly one symbol and adds none:
`dcache_clean_inval_poc` is no longer linked, retired by the by-name flush
resolver. The full host deck passes across all 23 runners in plain and
sanitizer modes (46 runs, clang r536225 in the DDK container), including
the new avc-spoof register contract, the flush-resolver resolution matrix,
and the rewritten redirect contract tests: publication with
generation-checked identities and nothing pinned, the full-table rewrite
handback, reserved targets, and the registration-state tests. A
second-round review added three things the suite covers now: the open
syscall entries themselves get their first host test (29 cases plus 3
source guards, pinning which opens the forward wrapper answers and which
it hands back, the fd/open/IN_OPEN ordering, the high-bit flag
truncation, and every openat2 validation edge), the maps face performs
its whole rule edit inside one rcu section instead of reading a rule
after the lock, and a freshly taken rule-table slot is published dead
before it becomes reachable. None of that changes what a resolver linker
reads.

A full on-device activation for this module is still pending; **SusFS LKM
remains experimental** until one activation passes on a BZIG device.

## Updating

1. Install **RootMyGalaxyUltra-1.2.24.apk** over the existing app; it uses the
   same package and release signing key.
2. If SusFS was activated with an earlier release, perform a **full reboot**
   first, then re-run SusFS activation so the updated module is loaded.

The boot helper does not need reinstalling for this update.
