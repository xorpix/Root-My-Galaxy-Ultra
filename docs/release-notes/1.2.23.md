## What's new

Module rebuilt from the 2026-10-23 upstream sync of the SusFS LKM (upstream
range `cc40d2d..d9c851d`, merged PRs #116 and #118 through #127, integrated as
module source `5c9a738`; upstream base `c2a5575` unchanged). Two headline
changes plus the hardening that ships with them:

- **Hidden paths can no longer be recreated.** A hidden folder or file stayed
  invisible in listings and lookups, but the create family did not: `mkdir`,
  `symlink` or `mknodat` on a hidden name succeeded and re-exposed it, and
  hard-linking (`linkat`) could bind an invisible name to a new directory
  entry. The module now carries a create gate (upstream issue #115): native
  and 32-bit create-family syscalls are intercepted through the patched
  syscall table, and a hidden target name is refused with the kernel's own
  error for that operation (`-EACCES` for the create attempts, `-ENOENT` for
  a hidden `linkat` old path), so returning apps see exactly what an absent
  path would tell them.
- **The module refuses to load unless its strong layers arm.** The
  syscall-table installation and the LSM hook installation are now dedicated
  lifecycle layers that pin their kernel tables and refuse the load with
  rollback when they cannot be resolved or patched (upstream PRs #119, #120).
  In exchange, the two askable gates degrade instead of failing: if the
  umount gate or the create gate cannot initialize on a given kernel, the
  load completes and just that feature stays off, with a single logged
  warning. Per-layer feature arming extends to the kernel interface (upstream
  PR #122): SHOW commands can no longer be answered for a feature whose
  layer never initialized, and the accepted command set plus
  `SHOW_ENABLED_FEATURES` cannot disagree.

Also from the sync: a fully hidden directory now reports the smallest address
record the ABI can express while keeping seekdir cookies intact (upstream PR
#124); both hide gates treat isolated app uids (99000-99999) as hidden without
asking the manager, matching the device's own marking (upstream PR #126); and
the hide-symbols probe demotes the ambiguous by-name caller case to a warning
so a shared `s_show` body no longer logs a false drift failure.

## Validation

Module size is 522,448 bytes stripped (was 498,272; the create-gate
machinery adds the two new imports: `inode_permission` and
`nop_mnt_idmap`, both used only by the create gate's parent permission check;
nothing was removed and every other kernel reference stays resolved by name at
runtime). The full host suite passes across all 20 runners in plain and
sanitizer modes, with the updated contract tests the sync needs: the dirent
runner pins the shrunken placeholder (minimal `d_reclen`, cleared native type
byte, header preserved on a mid-clear fault, `d_off` untouched), the lifecycle
runner pins the 15-row table splitting fatal refusal from per-feature drop,
and the module-filter runner gained the warning-path shim for the demoted
diagnostics.

A full on-device activation for this module is still pending; **SusFS LKM
remains experimental** until one activation passes on a BZIG device.

## Updating

1. Install **RootMyGalaxyUltra-1.2.23.apk** over the existing app; it uses the
   same package and release signing key.
2. If SusFS was activated with an earlier release, perform a **full reboot**
   first, then re-run SusFS activation so the updated module is loaded.

The bundled backends and boot helper are unchanged from 1.2.21. The boot
helper does not need reinstalling for this update.
