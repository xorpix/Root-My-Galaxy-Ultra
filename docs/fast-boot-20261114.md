# Immediate DirtyFrag boot start

Root before unlock no longer inherits the ordinary automatic-root settling delay. Existing saved
policies are effective immediately, including ones that still contain a 60-second or longer delay.
New policies and policy refreshes save zero. Android must still deliver the locked-boot event and
the authenticated helper and exact bundled firmware profile must be available.

The normal unlocked boot worker also bypasses the settling floor when the cache or selected retry
record names DirtyFrag. Unknown and legacy payloads retain their configured delay. Settings display
the effective delay as Off on matching DirtyFrag firmware and disable that inactive chooser.

The early worker retains its authoritative initial root check and avoids repeating that slow check
when no delay took place. Current policy, helper identity, firmware binding, kernel boot identity,
and the durable native-attempt claim are still checked before launching.

DirtyFrag readiness is adaptive for the normal unlocked boot worker as well as early root. The already-supported native
success marker can end the readiness window immediately; otherwise a completed saved-grant root
command can end it. The original bounded fallback remains when neither proof is ready. Native cleanup
and final backend verification still run after the wait. The trigger's reparenting and short preparation
pause are retained. This change does not diagnose or fix the separate unexpected reboot after soft reboot.

Validation covers saved long delays, cache-versus-retry payload selection, conservative legacy timing,
completed native markers, refused marker reads, root UID checks and real process deadlines. A signed
fast-boot-test1 APK is built with the full Android suite and payload/signature checks. Device timing
and the previously reported second reboot still require phone evidence.
